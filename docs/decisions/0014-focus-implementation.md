# ADR-0014: Focus implementation (advisories, no blocking)

**Status:** Accepted, implemented in `kepler-focus` and `kepler-policy` (refines ADR-0005)

## Context
ADR-0005 places Focus above the modules. Event kinds today are fixed (v1 envelope), Guardian owns blocking,
and a harness can only be cancelled where it exposes interception. Focus must stay optional and fail-safe.

## Decision
* Focus is an `OptionalModule` (`kepler-focus`) registered after Forge/Memory. It adds **no derived context** and
  never decides allow/deny. A new defaulted trait method `advise(&Envelope) -> Vec<Advisory>` is called by the engine
  for every event kind after the decision, inside the existing module time budget, with panics contained.
* The wire `Verdict` gets an **additive** optional `advisories` array (`source`, `level` = `info|warn|recommend_stop`,
  `code`, `message`). It is omitted when empty, so old adapters are unaffected. At most 4 per verdict, 240 chars each.
  Messages are generated by Kepler from counters and file names; they never contain the user's prompt or tool output.
* State is in memory, per session, bounded (64 sessions, LRU eviction; 16-entry call window; 256 tracked files;
  40 advisories per session; per-code cooldown of 12 events). Nothing is persisted. A new non-trivial user input
  restarts the task (counters/windows reset; only file names mentioned in the input are kept, never the text).
* Mechanisms implemented: scope lock (named files vs changed files, a justified exception is only a warning),
  loop detector (identical call with no file change in between; same failure; failure streak; A,B,A,B oscillating
  edits; a retry after a change is legitimate), adaptive budget (tool calls / elapsed time: `warn` while files change,
  `recommend_stop` only when over budget **and** no change for 30 calls), minimal-change guard (dependency manifests
  when the request does not mention dependencies; very large change sets), evidence/completion gate (reports
  *observed* verification after the last change, or "unknown"; `recommend_stop` after a pass and 8 idle calls).
* Enforcement per harness (KPL-033): Focus never blocks or cancels. Blocking stays with the Guardian preflight; a
  harness may surface advisories or ignore them. The Pi adapter does not display advisories yet.
* Disable with `KEPLER_FOCUS=off`; tune with `KEPLER_FOCUS_SOFT_TOOL_CALLS` and `KEPLER_FOCUS_SOFT_SECONDS`.

## Consequences
Cheap, deterministic supervision with auditable codes. All thresholds are hypotheses, **not calibrated**: the
baseline benchmark (KPL-032) was not run, and false-positive rates are unmeasured. Acceptance criteria are not
evaluated (Focus cannot know them); "verification" is a keyword heuristic over tool name/command.

## Alternatives
A new `Decision::Warn` (would change every consumer's match); a supervisor LLM (latency, tokens); hard timeouts
(kill productive work).
