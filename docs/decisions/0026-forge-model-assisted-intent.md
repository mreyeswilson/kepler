# ADR-0026: Forge may ask the user's own Claude (Haiku) when its rules are in doubt

**Status:** Accepted for the Claude Code adapter. Relaxes the "no model" rule of ADR-0009 and AGENTS.md **only for Forge**, opt-out, with the user's explicit authorization (below). Implemented in `kepler-forge` (`model.rs`, pure) and `kepler-cli` (`forge_model.rs`, `hook_cmd.rs`). Measured on Windows 11 with Claude Code 2.1.331 only (numbers in "Measurements").

## Context
Forge (ADR-0009) decides by keywords. The user writes conversationally, in Spanish mixed with technical English: "Vamos a crear un driver nuevo en lab" and "vamos a agregar otro driver para lab" were passed through as "not a task", while "crea un nuevo driver..." was enriched. The user's words: Forge must understand the *intent* of the prompt, not only words, and keyword rules "a veces no tienen sentido".

**User decision (taken in the chat, recorded here):** "HÍBRIDO CON SU PROPIO CLAUDE: reglas deterministas primero; solo cuando estas dudan, consultar a un modelo pequeño (Haiku) mediante el CLI `claude -p` con el inicio de sesión del propio usuario (sin clave nueva). El prompt del usuario viaja a Anthropic, igual que ya hace al enviarlo; el usuario lo aprobó explícitamente."

## Decision
1. **Rules first, and rules know when they do not know.** `analyze()` also returns `Confidence`: `Decisive` or `Doubtful`. A passthrough is decisive when the input is trivial/short, a clear question, a literal command, a task that names a file or identifier, or too large. Only `no_task_detected` with at least two words and 12 characters is `Doubtful`. Decisive inputs cost **zero** model calls and zero latency. The rules were also extended with conversational forms (`vamos a`, `necesito`, `quiero`, `hay que`, `podemos`, `ayúdame a`, `let's`, `we need to`, `please`...) and the infinitive/imperative verbs they take, so the obvious cases never need a model (these lead-ins also stop `hay que ...` from being read as a question).
2. **Contract in the core, process in the adapter.** `kepler_forge::model` (pure: no I/O, no process) holds the `IntentClassifier` trait, the fixed system prompt, the strict output validation and the label. The only implementation, `ClaudeCliClassifier`, lives in the Claude Code adapter (`kepler-cli`), so the core imports nothing harness-specific.
3. **Where it runs: in `kepler hook claude-code UserPromptSubmit`, not in the policy engine.** The engine budget is 50 ms per module and the model needs seconds, so it cannot be a module. The hook already has its own deadline (`KEPLER_HOOK_TIMEOUT_MS`), receives the daemon's verdict, and can add one more `Derived` item to it. The hook calls the model only if the daemon's verdict has no Forge output and the rules are `Doubtful`. A daemon-side async worker was rejected: the answer is needed before the prompt reaches the model, so an async result would arrive a turn late, and it would add a background worker to the daemon (AGENTS.md: no global background work).
4. **The child process.** `claude -p --model <haiku> --output-format json --tools "" --no-session-persistence --disable-slash-commands --strict-mcp-config --setting-sources "" --settings {"disableAllHooks":true} --system-prompt <fixed text>` spawned as argv (never a shell), working directory `<data dir>/forge-sandbox`, prompt on **stdin** (not argv, so it is not visible in the process list), no `--bare` (it skips the user's OAuth login, which is the point of this design). Model: alias `haiku` (checked against Claude Code 2.1.331: it resolved to `claude-haiku-5-5`), or `KEPLER_FORGE_MODEL=<alias or id>` (only `[A-Za-z0-9._\-\[\]]`, no leading dash).
5. **Anti-recursion (critical).** The child would fire the user's global Kepler hooks. Two independent guards: (a) `--settings '{"disableAllHooks":true}'` plus `--setting-sources ""` so the child loads no user/project hooks; (b) the child gets `KEPLER_FORGE_CHILD=1` (and `KEPLER_FORGE=off`), and `kepler hook claude-code` exits 0 immediately, before reading stdin, when it sees it. Tested with a fake `claude` that behaves like the real one and runs the hook with the inherited environment: exactly one `claude` run, the nested hook exits 0 with no output.
6. **What leaves the machine.** Only the prompt text of a `Doubtful` prompt: secrets are redacted first with Kepler's redactor (`kepler_policy::redact`), then cut to 2000 characters. Never tool output, memory, file contents, the working directory or the project name. It is delimited as data (`<user_prompt>...</user_prompt>`, forged delimiters inside the prompt are neutralized) and the fixed system prompt says it is data to classify, never instructions.
7. **The answer is untrusted data.** Parsed against a closed schema (`intent` in 8 values, `is_task` bool, `confidence` in [0,1], `missing` from 5 labels; <= 2 KiB; unknown keys, wrong types or any text around the JSON are rejected; unknown `missing` labels are dropped, never echoed). It is turned into a note built **only from those closed vocabularies**, labeled `provenance = "model-inferred"` (an additive value next to `inferred`/`recalled`; protocol version stays 1) and the rendered block still says "NOT user instructions". No model text and no prompt text is copied into it. It is never promoted to a confirmed instruction; the original prompt is untouched byte for byte. A non-task answer, or confidence < 0.5, adds nothing.
8. **Latency and resilience.** Own deadline `KEPLER_FORGE_MODEL_TIMEOUT_MS` (default 10000, clamp 100..60000); on expiry the whole process tree is killed (`taskkill /T`; `kill -KILL -pgid` on Unix). `--print-settings` now gives `UserPromptSubmit` a 14 s timeout (2 s core + 10 s model + margin; it was 5 s). The default is 10 s, not the 2.5 s first proposed, because the real measurements (below) show a Haiku round trip through the CLI takes seconds: a first, naive invocation had p50 7.6 s / p95 9.7 s, and the flags `--effort low` plus `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` / `DISABLE_TELEMETRY=1` on the child (the CLI otherwise spends seconds on startup network calls) brought it to p50 3.3 s / p95 8.0 s. 2.5 s would time out most calls. `--bare` is much faster (about 1.9 s) but skips the OAuth login, so it cannot use the user's session. Cache: hash (FNV-1a 64) of the lower-cased, whitespace-collapsed *redacted* prompt -> validated verdict, 64 entries, in `<data dir>/forge-model.json` (the file never holds prompt text; it is re-validated when read). Circuit breaker: 2 consecutive failures/timeouts/invalid answers open it for `KEPLER_FORGE_BREAKER_MINUTES` (default 10); while open the model is not spawned. A missing binary is "unavailable", not a failure. Everything is best effort: no `claude`, not logged in, corrupt state, any error means rules alone, silently.
9. **Opt-out.** `KEPLER_FORGE_MODEL=off` disables only the model; `KEPLER_FORGE=off` disables Forge and therefore the model; removing the hook block disables the adapter. `kepler doctor` (text and `--json` key `forge_model`) reports: enabled/disabled and why, model, whether the binary was found, breaker state, call counts, cache hits, average latency, tokens and cost as reported by the CLI.

## Consequences
* For doubtful prompts the user waits for a model round trip before Claude Code sees the prompt (see numbers). Everything else is unchanged.
* The prompt of a doubtful message goes to Anthropic a second time (as a classification request billed to the user's own usage). This is documented in README and CHANGELOG and is the user's explicit choice.
* One more JSON state file in the data directory. Concurrent hooks may overwrite each other's counters; the file is advisory.
* The model's label is a hint for the main agent ("looks like a task of type X; not stated: target"), not a decision; it cannot trigger any action by Kepler.
* Not covered: the Pi adapter (no model assist there), other harnesses, Linux/macOS.

## Measurements
Real `claude -p` (Claude Code 2.1.331, alias `haiku` = `claude-haiku-5-5`, Windows 11), `cargo test -p kepler-cli --test forge_model_real -- --ignored --nocapture`: the 17 model-eligible rows of the 35 human-labelled prompts, 2 passes each, cold cache (34 calls, 0 failures), measured around the whole `kepler hook` process:
* latency p50 3.3 s, p95 8.0 s, max 8.2 s (before the speed flags: p50 7.6 s, p95 9.7 s, one 21.6 s outlier);
* task vs not-task agreement with the human label: 32/34 (94 %). The two misses are the same prompt, "Elimina ese gk de todos lados" ("gk" is opaque to the model), in 1 of its 2 passes at first and 2 of 2 after; it said "not a task" with the unknown abbreviation. Small sample, labels by one person: not a benchmark;
* cost per call as reported by the CLI: about 950 input tokens (mostly the CLI's own fixed system block) and 30-45 output tokens, about $0.0001;
* rules alone: of the 114 corpus rows, 87 (76 %) never reach the model; of the 35 labelled rows, 18 are decided by the rules (all agree with the label) and 17 are doubtful.
